# Resumen de referencia para skill — Parametrización de ICON (Finanzas) (PAGE 791)
## 1) Conceptos clave (PAGE 791)
- Axional Finanzas es el núcleo económico-financiero y ocupa una posición central respecto a funcionalidades de Axional Suite; en el gráfico constan Compras, Ventas, Import/Exp., EDI, Almacén, etc. apuntando a Finanzas. (PAGE 791)
- La contabilización marca el documento origen como no editable y, con permisos, permite navegar entre el documento y los asientos generados; puede revertirse si las restricciones del programa y del negocio lo permiten. (PAGE 791)
- La configuración inicial de Maestros considera entorno empresarial unisociedad/multisociedad, entorno multipaís, datos maestros compartidos, consolidación, contabilidad de gestión y codificación; se organiza en generales, terceros, empresas y usuarios, más workflow y maestros de área. (PAGE 792)
- Validaciones y WorkFlow define condiciones de bloqueo, tipos de workflow, acciones, estados y grupos autorizantes para documentos y registros. (PAGE 794)
- Los numeradores de documentos definen series y números mediante expresión de máscara de serie y máscara de número, con justificación mediante ceros a la izquierda. (PAGE 797)
- Las cuentas contables cubren sistemas contables, planes, cuentas, mnemotécnicas, proyectos, secciones, grupos auxiliares y jerarquías; el PGC se crea por defecto en planes contables. (PAGE 799)
- Las cuentas contables de terceros se generan automáticamente desde el módulo de terceros y no es necesario crearlas previamente en relaciones contables. (PAGE 799, PAGE 901)
- Las alertas contables asocian un mensaje y un proceso a una o varias cuentas; al introducir o modificar apuntes se muestra la descripción y/o se activa el proceso UNIX asociado. (PAGE 964)
- Los permisos se estructuran jerárquicamente: Agrupación de permisos, Permisos pertenecientes a una Agrupación y Valores pertenecientes a un Permiso. (PAGE 795, PAGE 921)
- Los permisos se asignan a grupos de usuarios de finanzas (`cusergrp`) o gestión (`gusergrp`) desde la pestaña Permisos de los formularios de grupo. (PAGE 795, PAGE 921)
- Auxiliares y Parametrización mantiene diarios, sistemas, monedas, cambios, conceptos, calendarios, máscaras, proyectos, secciones y otros mantenimientos auxiliares. (PAGE 889)
- Usuarios distingue Tipo Administrador u Operador; el usuario `public` es genérico y la aplicación toma sus valores si no existe registro específico. (PAGE 894)
- Empresa define empresas operacionales y de consolidación, datos fiscales, datos contables, cuentas financieras y clasificación; para darla de alta primero debe existir como tercero. (PAGE 897)
- Ejercicio registra periodos contables, de coste, fiscales y tributarios; sus estados son A abierto, R regularizado, C cerrado definitivamente y H traspasado al histórico. (PAGE 900)
- Terceros son clientes, proveedores, bancos, etc.; nacen en estado Provisional y pueden pasar a Bloqueado o Activo según workflow. (PAGE 898)
- Auxiliares de Tercero cubren relaciones contables, direcciones, datos bancarios, condiciones de pago/cobro, mandatos SEPA y contactos. (PAGE 901)
- Documentos IGES incluye concursos (solo compras), ofertas, formularios, solicitudes (solo compras), acuerdos, planes de recepción (compras) o de entrega (ventas), pedidos, albaranes y facturas. (PAGE 733)
- Plantillas de contabilización requieren un patrón para cada posible origen de impactos a contabilidad; se registran mediante hojas de cálculo origen y destino. (PAGE 862)
- Contabilidad general registra y mantiene apuntes en diario en tiempo real; Extractos y Saldos cubren consultas de mayor, proyectos, secciones, terceros, movimientos, auditoría, saldos acumulados y vivos. (PAGE 857, PAGE 859, PAGE 860)
- El motor de consultas Excel dispone de funciones VBA `GetDecimalSeparator`, `AXIONAL` y `AX_Saldo`. (PAGE 973)

## 4) Circuitos, orden de carga y secuencia de pasos (PAGE 795)
- Permisos: primero se define la Agrupación de permisos; los Permisos pertenecen a una Agrupación; los Valores pertenecen a un Permiso. (PAGE 795, PAGE 921)
- Permisos: después se asignan desde los formularios de grupo de Finanzas o Gestión, pestaña `Permisos`, añadiendo y quitando permisos. (PAGE 795, PAGE 921)
- Empresa: primero se da de alta la empresa como tercero en el maestro de terceros; después se crea la empresa y se selecciona el tercero para autocompletar datos. (PAGE 897)
- Empresa: el contacto debe estar dado de alta en el maestro de contactos; la Zona impositiva influye en la jurisdicción de referencia y tipos de impuestos. (PAGE 897)
- Tercero funcional: tras crear un tercero, aunque pase a `Activo`, no es completamente funcional hasta definir como mínimo direcciones, relaciones contables, domiciliaciones contables, condiciones de pago y contactos. (PAGE 898)
- Ejercicio: para que un ejercicio pueda ser utilizado contablemente debe tener asociados los registros de periodificación; al crear el primer ejercicio se generan doce registros en periodos contables y periodos de impuestos. (PAGE 900, PAGE 868)
- Ejercicio: si existe ejercicio anterior se copia su periodificación; al abrir un ejercicio con anterior se regenera automáticamente el asiento de apertura. (PAGE 900)
- Documentos de compras/ventas: solo una vez definidos la empresa, los terceros, los artículos y las tipologías de documento es posible realizar un ciclo completo. (PAGE 734, PAGE 735)
- Tipologías: antes de dar de alta cualquier documento de compras o ventas hay que tener creada por lo menos una tipología para cada uno de ellos. (PAGE 734, PAGE 735)
- Ciclo básico de compras: se exigen tipologías `Pedido de compra directo`, `Albarán con origen pedido`, `Factura con origen albarán`. (PAGE 734)
- Ciclo básico de ventas: se exigen tipologías `Pedido de venta directo`, `Albarán con origen pedido`, `Factura con origen albarán`. (PAGE 735)
- Circuitos documentales: `Pedido → Albarán → Factura`, `Oferta → Pedido → Albarán → Factura`, `Acuerdo → Albarán → Factura`, `Pedido de compra → Pedido de venta → Albarán de venta → Albarán de compra → Factura de venta → Factura de compra`, `Albarán de abono → Factura de abono`; se pueden definir circuitos de hasta seis documentos o más. (PAGE 733)
- Numeradores: se asignan a los tipos de documento; por ejemplo, facturas de venta en `gvenfacd` y facturas de compra en `gcommovd`. (PAGE 797)
- Plantillas de contabilización: para cada posible origen de impactos a contabilidad se requiere disponer de un patrón de contabilización. (PAGE 862)
- Cuentas de terceros: no es necesario crear previamente la cuenta contable; el sistema la crea automáticamente durante la validación de la relación contable y la asocia al tercero. (PAGE 799, PAGE 901)

## 5) Procesos, botones y acciones con efecto (PAGE 791)
- Contabilización: implica dos efectos principales; el documento origen queda marcado como no editable y, si se tienen permisos, permite navegar entre él y los asientos contables generados; prácticamente todas las áreas permiten revertir contabilizaciones si las restricciones lo permiten. (PAGE 791)
- Permiso `Contabilizar`: puede tener valores `Real` y `Diferido`; sin permiso no se contabiliza; con valor se contabiliza en real o en diferido. (PAGE 795, PAGE 921)
- Workflow: si no se cumple una condición de bloqueo, se requieren acciones concatenadas de autorización; las acciones se obtienen del estado inicial definido para el código de bloqueo. (PAGE 794)
- Numerador: la serie y la máscara de número generan el número de documento; la justificación con ceros a la izquierda forma parte de la máscara. (PAGE 797)
- Alertas: si el usuario tiene permisos se habilita crear, modificar y eliminar alertas; al introducir o modificar apuntes en una cuenta con alerta se muestra la descripción y/o se activa el proceso UNIX asociado. (PAGE 964)
- Permisos: los permisos estándar no pueden modificarse ni borrarse desde los formularios de parametrización; solo se asignan permisos de módulos activos en la base de datos. (PAGE 795, PAGE 921)
- Funciones de permiso: `cuserauth_allow(agrupación, permiso, valor)` en Javascript y XUDF `cuseraut_allow(usuario, agrupación, permiso, valor)`. (PAGE 795, PAGE 921)
- Empresa: al seleccionar un tercero se autocompletan `Identificación fiscal`, `NIF-Empresa`, `País emisor`, `Dirección fiscal`, `País`, `Zona impositiva` e `Idioma`; el contacto fiscal debe existir previamente. (PAGE 897)
- Tercero: se ejecuta la consulta, se rellenan obligatorios, se pulsa botón o se despliega `Guardar y abrir`, y se valida; si pasa a `Bloqueado`, hay que verificar requisitos del workflow. (PAGE 898)
- Tercero: si no tiene workflow o cumple el workflow, puede pasar a `Activo`; si queda pendiente, puede pasar a `Bloqueado`. (PAGE 898)
- Ejercicio: acciones `Regularizar ejercicios`, `Cierre Temporal`, `Cierre Definitivo`; un ejercicio puede abrirse, cerrarse o regularizarse varias veces. (PAGE 900)
- Ejercicio: al borrar un ejercicio se borran periodos contables e impositivos asociados, pero no la información contable (apuntes, saldos, etc.). (PAGE 900)
- Pedido de compra: `Compras/Pedidos/Nuevo pedido`; pulsar `insertar` para cabecera; pestaña `Líneas`; pulsar `insertar` línea; `Grabar`; `Limpiar`; volver a pestaña `Pedido compras`; pulsar `VALIDAR`. (PAGE 734)
- Albarán de compra: `Compras/Albaranes/Nuevo albarán`; seleccionar tipo con origen pedido; rellenar empresa/almacén/delegación/departamento; introducir número de pedido; pulsar `insertar`; modificar líneas y `Grabar`; pulsar `Validar` si se modificaron cantidades. (PAGE 734)
- Albarán de compra: si contiene 100% de cantidades, el pedido pasa a `Servido`; si se modifica cantidad, el pedido pasa a `Parcial`. (PAGE 734)
- Factura de compra: `Compras/Facturas/Nueva factura`; seleccionar tipo con origen albarán; rellenar datos; pulsar `insertar`; pestaña `Albaranes compras conformar`; seleccionar albarán; pulsar `Conformar`; volver a cabecera y pulsar `Validar`; la tipología no puede modificarse una vez creada la cabecera. (PAGE 734)
- Entrada Rápida de Tercero: si se informa el campo `IBAN`, el sistema genera un registro de domiciliación bancaria para el tercero actual y genera dirección principal, datos de cliente/proveedor o delegación según el tipo, adoptando valores por defecto. (PAGE 915)

## 6) Advertencias y errores típicos (PAGE 795)
- Los permisos estándar no pueden modificarse ni borrarse desde los formularios de parametrización; solo se asignan permisos de módulos activos en la base de datos. (PAGE 795, PAGE 921)
- Si la serie incluye `#d` y el formato del número no incluye `#d`, puede haber problemas de unicidad porque cada serie tiene contador independiente; la conversión de series ya definidas no dispone de solución desasistida. (PAGE 797)
- Si no se cumple una condición de bloqueo, se requieren acciones concatenadas de autorización; las acciones se obtienen del estado inicial definido para el código de bloqueo. (PAGE 794)
- Las alertas no son vinculantes; la aplicación no puede responsabilizarse de que los usuarios cumplan los avisos. (PAGE 964)
- Para PDF/A las fuentes deben estar incrustadas y su licencia debe permitirlo; Helvetica, Courier y Times como Base-14 sin incrustación no cumplen por sí solas PDF/A; Factur-X no garantiza conformidad PDF/A; CMC-7 exige impresión MICR. (PAGE 1111)
- Si el campo precio está a 0 y se inserta el artículo, se aplica precio de tarifa si existe. (PAGE 734)
- En factura de compra, la tipología no puede modificarse una vez creada la cabecera. (PAGE 734)
